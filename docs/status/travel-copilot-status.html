  • The fallback on the SE 3. On a phone without Apple Intelligence our routing still sends requests straight to the cloud, so Firebase never falls back there. About an hour of work keeps them on the hybrid route.

  • App Check outside debug. Only the debug provider is set up; TestFlight needs App Attest and a developer account.
App map

How the app is put together

Screens never call AI directly. They go through AIService, which asks the routing policy where a task should run, sends it through Firebase AI Logic, and logs the result. Bookings and answers are stored on the phone in SwiftData.

User flow

How a traveler uses it, start to finish

Before the trip the app needs the internet once to read bookings and save maps. During the trip everything a traveler needs works with no signal.

Hybrid routing

How each AI request picks device or cloud

Every request has a kind. Survive is help during the trip, so it prefers the phone. Prepare is set-up work that needs the cloud. Catch-up improves offline drafts and answers waiting questions on good Wi-Fi. Open questions to Blue go to the cloud, or wait when offline.

Blue

How a Blue chat answer is made

The on-device model never writes the answer. It only picks which booking and which field the question is about; the app shows that stored value. A keyword check stops small talk from getting a booking value.
